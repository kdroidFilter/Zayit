## Vision
Zayit is a dream turned useful: a natural, fluid, almost obvious study experience.
The project will remain free by principle. Support is welcome and meaningful.
It is designed to stay non-commercial.
With God's help, Zayit will keep growing without losing its spirit.

## In the spirit of a study hall
Zayit is designed like a digital study hall: stable, fast, consistent.
You feel the calm of study: everything works, everything is in its place.
The text stays at the center, with respect and without distractions.

## A pro and natural interface
Zayit is built on JetBrains technologies, including Compose Desktop and Jewel.
Inspired by Google Chrome and IntelliJ IDEA, it offers a professional interface
that is fluid and natural, respects study, and does not strain the eyes.
Zayit is easy to use: you already know how, no learning curve.
Tabs, windows and virtual desktops work the way Chrome does: drag a tab out into its own window, pin it, reopen the last one closed.

## An exceptional search engine
One smart bar for everything: books, authors, references and text. Type and go straight to the right place.
Powered by Lucene and by Zayit's own embedding model, it finds passages by their words and by their meaning.

- Type a reference like `חולין יב` or `בראשית א ג` and land on it.
- Books by name or acronym, authors with their own page, all from the same bar.
- Semantic search: find a passage by its meaning, not only its words.
- Even without vocalization, from a partial word or an approximate spelling.
- Clean results by category, each passage read in its context beside the list; a click opens the book right there.
- Find in the whole book, like Ctrl+F.

## What Zayit lets you do
- Find a passage in seconds, by its words or its meaning.
- Explore the library by book and table of contents without losing the thread.
- Search inside a book to prepare a lesson or review.
- Show commentaries, targumim and sources side by side.
- Work in tabs, windows and virtual desktops, like Chrome.
- Keep bookmarks in folders and a full visit history.
- Highlight words and add your notes, right on the text.
- Copy a clean excerpt with its source, or share the exact place.
- Back up your notes and settings to Google Drive.
- Get automatic updates, the library included.
- Work from the keyboard: Ctrl+F, Ctrl+Shift+T, Alt+Home and more.
- Choose light or dark, your accent color and your fonts.

### Getting started

Clone the repository with submodules:

```bash
git clone --recurse-submodules https://github.com/kdroidFilter/Zayit.git
```

**Important:** You must use JetBrains Runtime 25 (JBR 25) as your `JAVA_HOME`.

### Architecture guidelines

**Project structure:**
- `SeforimApp/` — Main desktop application (Compose Multiplatform)
- `SeforimLibrary/` — Composite build: `core` (domain models), `dao` (SQLDelight persistence), `generator` (data pipeline, JVM only)

**Dependency injection (Metro):**
- Access the DI graph via `LocalAppGraph.current`
- Use `@AssistedInject` + `@AssistedFactory` for ViewModels

**Naming conventions:**
- `*ViewModel` for ViewModels
- `*View` for UI components
- `*State` for UI state data classes
- `*Event` for user action types

**Tab system:**
- Each screen must know its `tabId`
- Use `remember(appGraph, tabId)` to create ViewModels
- Use `TabStateManager` for tab-scoped state persistence

**Source sets:**
- Shared code in `commonMain`
- Platform-specific code in `jvmMain`
- Platform types must not leak from `jvmMain` to `commonMain`

For detailed documentation, see `CLAUDE.md` and `TAB_SYSTEM_README.md`.

## Open core
Zayit is **open core**. Everything in this repository is free and open source under the AGPL v3 (with the §7b term
above), and builds into a complete application.

The **official builds** (the releases of this repository and of [zayitapp.com](https://zayitapp.com/)) also include
proprietary modules, which are not open source and live in private repositories:

- **The smart siddur** (סידור חכם): the tefilot of every day, complete, after the user's nusach and place
  (`io.github.kdroidfilter:seforim-siddur`, from the private SeforimSiddur repository). Its screen is in
  `SeforimApp/addons/siddur/enabled`.
- **The semantic search**: Zayit's own embedding model, which finds passages by meaning and not only by their words
  (`io.github.kdroidfilter:seforim-semantic` and its model, from the private SeforimEmbedding repository). Its engine is
  in `SeforimApp/addons/semantic/enabled`; the model is inside that package, never in the library's database.

A build without access to these modules (any build from this repository by default) leaves them out: the menus do not
show them, the search is lexical only, and everything else works the same (`SeforimApp/addons/*/disabled`). A
database you generate yourself has no dense vectors either. A build includes the smart siddur when
it can read its package: with `siddur.token` in `~/.gradle/gradle.properties`, the `SEFORIM_SIDDUR_TOKEN` variable
(CI), or a `gh` CLI logged in to an account that can see the repository (with the `read:packages` scope); or from its
sources beside Zayit's, with `-Psiddur.local=true` (`../SeforimSiddur`).
The semantic search likewise, with the siddur's token (or `semantic.token`, `SEFORIM_SEMANTIC_TOKEN`, `gh`), or with
`-Psemantic.local=true` (`../SeforimEmbedding/semantic`). With that token, SeforimLibrary's generator also embeds the
corpus into the search index's dense vectors (`:searchindex:embedCorpus`, on an NVIDIA GPU); without it, the index it
builds is lexical only.

With `gh`, the default login has no `read:packages` scope; add it once, then check the package is readable (it prints
`seforim-siddur`) and re-sync Gradle:

```bash
gh auth refresh -h github.com -s read:packages
gh api users/kdroidFilter/packages/maven/io.github.kdroidfilter.seforim-siddur --jq .name
```

Contributions go into the open core; the [CLA](CLA.md) lets them ship in the official builds as well.
